# AI-тестировщик API

Web-инструмент для автоматической генерации и выполнения тест-кейсов для любого REST API,
описанного спецификацией OpenAPI. Использует LLM через **GPTunnel** (OpenAI-совместимый прокси)
для интеллектуального анализа спецификации и построения реалистичных сценариев.

Интерфейс: FastAPI + SSE-стриминг прогресса. Вся работа — через браузер.

---

## Возможности

- Парсинг спецификаций OpenAPI 3.x и Swagger 2.x (JSON и YAML)
- **Двухэтапная генерация** тестов через LLM:
  1. Планирование сьюта (модель видит всю спеку, составляет план)
  2. Детализация каждого теста (модель получает только релевантные фрагменты)
- Три типа тестов:
  - **stateless** — независимые тесты отдельных эндпоинтов
  - **contextual** — многошаговые бизнес-сценарии (регистрация → вход → создание → удаление)
  - **status_code** — точная проверка HTTP-кодов (401, 403, 404, 422 и др.)
- Асинхронное выполнение через `httpx`
- Извлечение значений из ответов (токены, ID) через JSONPath и подстановка в последующие шаги
- Пропуск зависимых шагов при падении предшественника
- Real-time прогресс в web-UI через Server-Sent Events
- JSON-отчёт с раскрывающимися деталями по каждому шагу

## Требования

- Python 3.11+
- API-ключ GPTunnel: переменная окружения `GPTUNNEL_API_KEY`

## Установка и запуск

```bash
cd api_tester
pip install -r requirements.txt

# Linux/macOS
export GPTUNNEL_API_KEY="ваш-ключ"
# Windows PowerShell
$env:GPTUNNEL_API_KEY = "ваш-ключ"

# Запуск сервера
python -m uvicorn web_app:app --host 0.0.0.0 --port 8000
```

Затем открыть `http://localhost:8000` в браузере.

## Что умеет интерфейс

- **Новый прогон** — загрузка OpenAPI-спеки drag-n-drop, настройка модели, авторизации,
  параметров генерации. Real-time прогресс: видно, какой тест сейчас генерируется
  или выполняется.
- **История** — список всех прошлых прогонов с сводкой (прошло/провалилось/время).
  Переживает рестарт сервера — читает `runs/<run_id>/` с диска.
- **Просмотр отчёта** — раскрывающиеся карточки тест-кейсов, по каждому шагу видны
  запрос, ответ, ожидаемый и полученный статус-коды.
- **Скачивание JSON** — полный отчёт в машиночитаемом виде.

### Структура хранения

```
runs/
└── <run_id>/
    ├── meta.json          # метаданные прогона
    ├── <filename>.json    # исходная спека пользователя
    ├── suite.json         # сгенерированный тест-сьют (для отладки)
    └── report.json        # итоговый отчёт выполнения
```

### API-эндпоинты

| Метод | Путь                                 | Назначение                          |

| GET   | `/api/runs/{id}/suite`               | Сгенерированный сьют (для отладки)  |

## Конфигурация

Скопируйте пример конфига и заполните значения:

```bash
cp config.yaml.example config.yaml
```

Поддерживается подстановка переменных окружения через синтаксис `${ИМЯ_ПЕРЕМЕННОЙ}`.
Файл `.env` в текущей директории загружается автоматически.

```yaml
auth:
  type: bearer          # bearer | api_key | none
  token: "${API_TOKEN}"

test_settings:
  timeout: 30
  delay_between_requests: 0.5

ai_settings:
  model: gpt-4o
  max_test_cases: 20
  include_negative_tests: true
  include_edge_cases: true
```

## Калькулятор стоимости

Перед каждым прогоном интерфейс показывает **ожидаемую стоимость** в рублях на
основе размера вашей спеки, выбранной модели и `max_tests`. После завершения
рядом выводится **фактическая стоимость** по данным `usage` из ответов GPTunnel,
с отклонением в процентах от оценки.

**Источник цен:**
- В коде (`cost_estimator.py`) есть встроенные дефолты для популярных моделей
  (GPT-4o/mini/o1, Claude Opus/Sonnet/Haiku 4.6, Gemini 2.5 Pro/Flash).
- Секция `pricing.models` в `config.yaml` переопределяет дефолты и позволяет
  добавлять новые модели. Формат — рубли за 1 миллион токенов, раздельно
  для input/output. См. `config.yaml.example`.

**Точность оценки:** погрешность около ±30%. Оценка основана на реальных
размерах промптов (Planner + N×Generator) и среднем распределении типов
тестов. Для очень маленьких или очень больших спек ошибка может быть выше.

**Где отображается:**
- В форме нового прогона — автоматически при выборе файла/модели
- В Live-панели после завершения — сравнение факт vs оценка
- В списке истории — фактическая стоимость каждого прогона
- В детальном отчёте — в блоке сводки

## Как работают контекстные тесты

Контекстные тесты имитируют реальные пользовательские сценарии. Модель генерирует шаги с:

1. **`extract`** — JSONPath для извлечения значений из ответа:
   ```json
   "extract": {"token": "$.access_token", "user_id": "$.data.id"}
   ```

2. **`{{variable}}`** — шаблоны для подстановки в последующие шаги:
   ```json
   "headers": {"Authorization": "Bearer {{token}}"},
   "endpoint": "/users/{{user_id}}"
   ```

3. **`depends_on_vars`** — если переменная не извлечена (предыдущий шаг упал),
   зависимый шаг автоматически пропускается со статусом `skipped`:
   ```json
   "depends_on_vars": ["token", "user_id"]
   ```
